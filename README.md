# dsh-memory

**给你的 AI 装上不会忘的记忆。**

每次开新会话，AI 都从零开始 —— 昨天定的方案、上周踩的坑、你的偏好，全都不记得了。

dsh-memory 给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）补上这一块：**跨会话记住该记的，忘掉该忘的，还不会记串。**

---

## 它做什么

**记住事实，不记流水账.**
你说过的「发布分支叫 `release`」「周报周五下午发」——它归成一条条事实存下来，下次开口它就记得。事实变了就**追加新版本，旧版本永远留着**（所以它能回答"这个是什么时候改的、为什么改"）。

**每次开口，先递一份简报.**
新会话一开始，它把当前状态摘要交给模型 —— 模型不用重新摸索你之前干到哪了。

> 靠宿主的 `systemPrompt` 服务实现：一段**字节稳定**的能力说明常驻系统提示，简报和记忆目录走动态快照（只在内容变了才变，不破 prefix 缓存）。宿主没有这个服务时，模型得自己想起来调 `memory_brief`。

**长了自己分家.**
事实攒多了（默认超过 80 条）会按主题拆成多个文件，配一份索引；检索先按索引挑文件，判不准就全读——**宁可慢，不会漏**。

拆之前会让模型提分组方案，但**落盘分组由代码裁定**：编造的 id 丢掉、漏掉的进 `unsorted`，一条都不许丢。

> **只在第一次拆的时候问模型。** 之后新事实走**纯代码增量归属**：按标签进已有分片，进不去就进 `unsorted`，攒够一批才再问一次。这样分片名不会一轮一个样、日常整理也不多烧一次模型调用。

**夜里自己整理.**
到点自动扫一遍最近聊的，把反复出现的线索整理进长期记忆、更新简报。**只加，不删。**

> 需要 profile 里有 `schedule` 服务（如 `dsh-experimental-schedule-bundle`）。没有该服务时不会自动跑，手动调 `memory_organize` 一样能整理。
>
> 整理走的是**宿主自己的模型服务**（`ctx.llm`）——PC 上就是你在 dsh 里配的那套，手机上就是 App 里填的那个 provider。**插件不另配 API key，也不需要单独开什么代理。** 默认跟随宿主的默认模型，想指定就在配置里写 `organizer_provider` + `organizer_model`。

## 记忆会过期，所以它提醒你核验

存下来的是**写入那一刻的断言**，不是现值。文件改了、配置换了，记忆不会自己跟着变。所以：

- 系统提示里常驻一条硬规则：涉及文件名、路径、配置值时，**行动前先核验当前状态**
- `memory_recall` 命中里含具体路径/配置时，结果末尾附一句提醒
- 查不到时**不返回空列表了事**，而是给出下一步：换更少更独特的词 → 按标签查 → 看简报

**0 命中 ≠ 从未记录。** 一次查不到不代表没有——换个措辞就是另一条命中。

## 数据长什么样

全在 `$DSH_HOME/memory/`（默认 `~/.dsh/memory/`，可用 `memory_dir` 改）：

```
memory/
  brief.md              L4 启动摘要（Markdown，人可读）
  facts.yaml            L3 事实（分片之前都在这里）
  candidates.yaml       L2 待确认线索
  facts/                分片之后的事实（超过阈值才出现）
    _index.yaml         分片索引（缓存，可删，删了不影响任何事实）
    config.yaml         ← 按主题拆出来的分片
    project.yaml
    unsorted.yaml       ← 归不进去的兜底，永远不丢
  .archive/             旧的 facts.yaml 归档（移动过来的，不删）
  log/YYYY-MM-DD.json   每次整理的诊断日志（追加式）
  .sessions.json        已处理会话台账
```

一条事实长这样：

```yaml
- id: "mem-1792927799706-001"
  fact: "发布分支"
  since: "2026-03-02"
  history:                      # 版本链，最新一条 = 当前值
    - date: "2026-03-02"
      value: "release"
    - date: "2026-04-18"
      value: "stable"
      note: "用户要求改名"
```

**改值只追加新版本**，旧的永远在 `history` 里 —— 所以它能回答"这个是什么时候改的、为什么改"。

## 为什么不是又一个「记忆 RAG」

大多数「AI 记忆」是个黑盒向量库 —— 存进去的东西，你看不见、动不了。

dsh-memory 反过来：**记忆就是几个明文的文件**，躺在你自己的磁盘上。

- 你**能打开看**（Markdown + YAML，不是二进制黑盒）
- 你**能手动改**（记错了不用求 AI 忘掉，自己改）
- 你**能搬走**（换成别的工具也读得懂）
- 而且「只追加不删」是**写死在代码里**的 —— 它不可能偷偷把你的事实抹掉

## 装上

```bash
dsh plugin --profile <你的profile> add <这个包 / 包名 / GitHub 地址>
```

装上即挂载，六个工具立刻可用。夜间自动整理还需要 profile 里存在 `schedule` 服务（见上），没有的话手动整理一样能用。

**不需要配 API key，也不需要开代理** —— 整理用的是 dsh 自己的模型服务，你在哪儿配的模型就用哪儿。

想调的话，在 profile 的 `cordis.patch.yml` 里覆盖：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `memory_dir` | `$DSH_HOME/memory` | 记忆存放目录 |
| `organizer_provider` | *跟随宿主* | 整理用的 provider，留空 = 用宿主默认模型 |
| `organizer_model` | *跟随宿主* | 整理用的模型名，留空 = 用宿主默认模型 |
| `daily_time` | `04:00:00` | 夜间整理时间（本地时区） |
| `time_zone` | 宿主时区 | IANA 时区名 |
| `scan_sessions` | `12` | 每次整理最多扫多少场会话（上限 40） |
| `shard_threshold` | `80` | 事实超过多少条开始分片；设 0 关闭 |
| `enable_shard` | `true` | 完全关闭分片 |
| `enable_schedule` | `true` | 关掉自动注册夜间任务（只留工具） |
| `organizer_session` | `memory-organizer` | 整理专用会话 id（整理时跳过它自己） |

## 整理的时候到底发生了什么

一次 `memory_organize`（手动调或夜里自动跑）走这几步，顺序是固定的：

1. **收拢重复候选** —— 同义的待确认线索合成一条，多余的标 `merged` 保留（不删）
2. **扫会话** —— 读最近几场，剔掉整理会话自己和子 agent 会话（**按 id 剔，不按文本**）
3. **问模型** —— 把会话摘录 + 现有事实 + 现有候选 + 当前简报一起给它，要一份 JSON
4. **落地** —— 事实追加版本、候选去重后新增、简报换新（旧的归档）
5. **分片** —— 事实超阈值时见上

**它不会做的事**（这些都有负面清单管着）：

- 不会把**整理过程本身**写进记忆（"我今天扫了几场"这类）
- 不会记**绝对路径、主机名、端口**，除非用户明确要求长期记住某个地址
- 不会把**一次性的状态**写成事实
- 模型输出解析不了就**什么都不写**（宁可不记，不编造）

> 简报更新、事实追加、候选归并都是**只加不删**：旧简报进 `log/` 归档，旧事实版本留在 `history`，被合并的候选标 `merged` 仍可见。代码里没有任何删除历史条目的路径。

## 它给了 AI 六只手

| 工具 | 做什么 |
|---|---|
| `memory_brief` | 读当前简报 |
| `memory_recall` | 按关键词 / 标签翻记忆 |
| `memory_note` | 记一条事实（同主题自动出新版本） |
| `memory_candidate` | 记一条「待确认」的线索 |
| `memory_promote` | 把线索升格成正式事实 |
| `memory_organize` | 手动整理一次（`dry_run` 只看报告不落盘；`reshard` 强制重排分片） |

## 兼容

- **dsh 0.2.x** —— 记忆工具 + 简报注入；profile 有 `schedule` 服务时才有夜间自动整理
- **dsh 0.1.x** —— 自动降级：记忆工具照用，只是不注册定时任务
- **没有 `systemPrompt` 服务的宿主** —— 能力块不注入，模型靠工具描述自己判断
- **没有 `llm` 服务的宿主** —— 六个工具照用，但整理会明确报"无法整理"
- **PC 与手机（dsh 安卓版）同一份包**

## 已知边界

- **`memory_recall` 是子串匹配，不是语义搜索** —— 换个措辞可能查不到。所以 0 命中时会给出升级路径，别当成"没记过"。
- **候选去重只认"摘录腔"** —— 会剥掉 `（出现 N 次）` 这类格式尾巴，但真正换措辞的说法仍可能分成两条。**这是有意的：误合并会丢线索，比多存一条更糟。**
- **整理会让模型判断"什么值得记"** —— 它可能漏记，也可能多记。事实都在明文文件里，看不过去直接手改就行。
- **分片后新增的事实先进 `unsorted`** —— 下次整理才按标签归位。这是为了让分片布局稳定，不是丢数据。
