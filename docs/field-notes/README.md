## 所以它到底记住了什么

上面两张图里，它记得的东西不止一种。仔细看会发现它比预想的好：

| 它说的 | 真正的性质 | 现状 |
|---|---|---|
| 「Steam 排序还停在游戏时间，你之前说要换回最近玩过」 | **纯欠债**（待办） | ✅ 靠候选机制 |
| 「9 点开会那条迟到 21 小时才弹，**比不弹还吓人**」 | **行为后果的翻车**，而且它自己给了判据 | ✅ **做到了** |
| 「Shizuku 一掉线我就只剩无障碍那条腿，点 Steam 这种**没控件的界面就哑了**」 | **能力断档的翻车**——条件 + 场景 + 结果，完整的因果链 | ✅ **做到了** |

第 3 条尤其值得看：它说的不是「我没有 root 权限」（那是事实），而是「**掉线 + 无控件界面 = 哑**」——**这是因果，不是状态**。

这正好是它在第二张图里想要的「记得住那次点击为什么没反应」。**它已经做出来了，只是把它说成了「我缺什么」，没归类成「我踩过什么坑」。**

### 所以真正缺的是检索，不是记录

上面的因果**都记下来了**。缺的是**下一次遇到同类场景时，能不能主动想起来**。

举例：它记得「Steam 这种无控件界面 + Shizuku 掉线 = 哑」。但下次又碰到一个无控件的界面时，它会不会**先想起这条**、而不是先试一遍再发现点不动？

**记下来和想得起来是两件事。** 前者是存储问题，后者是检索问题——而检索要的是一条**触发线索**（"无控件界面"这个特征），不是全文。

### 另外两类确实还缺

| 类型 | 现状 |
|---|---|
| **流程细节**（那个 docx 为什么那样排） | ⚠️ 整个丢了，只剩「做过」 |
| **聊了一半的话题** | ⚠️ 没有这个概念，按会话切块就断了 |

「聊了一半」最麻烦：它要求跨会话识别「同一件事」。而**判断一个话题是放弃了还是暂停了**，人靠感觉，模型只能靠规则。

这一节存在的意义，是区分「它看起来记得」和「它真的记得」——以及区分**「记得」和「想得起来」**。
